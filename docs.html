TalkConnector API

TalkConnector는 카카오 상담톡 API를 셀프서비스로 제공합니다. 카카오 허브파트너 등록, 발신프로필 등록, 수신 도메인 설정, ACL 등록 같은 절차는 TalkConnector가 대신 처리하고, 고객사는 REST API와 서명된 웹훅만 연동합니다.

구분내용
Base URLhttps://api.talkconnector.example (정식 도메인 확정 전 가칭)
프로토콜HTTPS, JSON (업로드만 multipart/form-data)
인증Authorization: Bearer tc_test_... 또는 tc_live_...
수신고객사 HTTPS 엔드포인트 1개로 모든 이벤트 전달, HMAC-SHA256 서명
버전/v1 경로 버전. 하위 호환이 깨지는 변경은 새 버전으로 제공

카카오 상담톡 API와의 차이

항목카카오 상담톡 API 직접 연동TalkConnector
사전 준비허브파트너 계약, 발신프로필 등록, 수신도메인·ACL 등록가입 후 콘솔에서 채널 인증
식별자partner_key(경로), sender_key(본문)channelId 하나
메시지 일련번호고객사가 serial_number 생성서버가 생성, 선택적으로 clientMessageId로 중복 방지
발송 경로plain, rich 경로 분리POST /v1/messages 하나, type으로 구분
수신경로 6개(/message, /reference 등)를 모두 구현엔드포인트 1개, type으로 구분, 서명 포함
테스트테스트용 허브파트너 별도 등록테스트 채널과 tc_test_ 키 즉시 제공

빠른 시작

가입부터 첫 테스트 웹훅 수신까지 3분 안에 끝나도록 설계했습니다.

  1. 가입: 구글 또는 카카오 계정으로 로그인하고 약관에 동의합니다.
  2. 채널 연결: 카카오톡 채널 검색용 아이디와 관리자 휴대폰으로 인증하면 채널 ID와 테스트 API 키가 발급됩니다.
  3. 웹훅 등록: 수신 URL을 저장하고 테스트 이벤트를 보내 2xx 응답을 확인합니다.
  4. 카카오톡에서 채널에 메시지를 보내면 message 이벤트가 도착합니다. 받은 userKey로 답장합니다.
curl -X POST https://api.talkconnector.example/v1/messages \
  -H "Authorization: Bearer tc_test_xxxxxxxxxxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{
    "channelId": "ch_8f2k1m9x0a7q",
    "userKey": "aBcD3fGh12Ij",
    "type": "text",
    "text": "안녕하세요. 무엇을 도와드릴까요?"
  }'
{
  "ok": true,
  "data": { "serial": "tc_01JBQ7Y2N4M8", "createdAt": "2026-11-24T10:15:02.511+09:00" },
  "requestId": "req_7Hq2Lr0pXz"
}

인증

모든 요청은 Authorization 헤더에 API 키를 Bearer 토큰으로 넣습니다. 키가 없거나 폐기되었으면 401 UNAUTHORIZED를 반환합니다.

Authorization: Bearer tc_live_9xK2mQ7vR4tY8wZ1aB3cD5eF6gH0jL2n

키 종류

키형식용도
테스트 API 키tc_test_ + 32자테스트 채널 호출. 과금 없음
운영 API 키tc_live_ + 32자운영 채널 호출. 상담방 과금
웹훅 서명 키whsec_ + 32자수신 웹훅 서명 검증. 고객사별 발급
채널 IDch_ + 12자요청 대상 채널 지정

테스트 키로 운영 채널을, 운영 키로 테스트 채널을 호출하면 403 ENV_MISMATCH를 반환합니다.

권한 범위

권한허용 작업
read 조회내 정보, 채널, 상담 세션, 인증 상태, 사용량 조회
write 발송조회 + 메시지 발송·발신 취소, 읽음 처리, 상담 종료·연장, 고객 차단, 파일 업로드
admin 관리발송 + 상담시간 변경

키 관리 원칙

  • 키는 발급 직후 한 번만 전체 표시되며 서버에는 해시로만 저장됩니다.
  • 재발급하면 기존 키는 즉시 폐기됩니다. 무중단 교체가 필요하면 새 키를 추가 발급해 배포한 뒤 기존 키를 폐기하세요.
  • 키 발급·폐기, 서명 키 조회는 콘솔 접근 이력에 기록됩니다.
  • 키를 브라우저나 앱에 넣지 마세요. 서버에서만 호출해야 합니다.

요청·응답 규칙

모든 응답은 같은 봉투를 씁니다. HTTP 상태 코드와 ok 값을 함께 확인하세요.

// 성공
{ "ok": true, "data": { ... }, "requestId": "req_7Hq2Lr0pXz" }

// 실패
{
  "ok": false,
  "error": {
    "code": "NO_SESSION",
    "message": "상담 세션이 없는 고객에게는 메시지를 보낼 수 없습니다.",
    "kakaoCode": null
  },
  "requestId": "req_7Hq2Lr0pXz"
}
  • requestId: 문의 시 함께 알려 주세요. 응답 헤더 X-Request-Id에도 있습니다.
  • kakaoCode: 카카오 상담톡 API가 오류를 반환한 경우 원본 코드를 그대로 전달합니다.
  • 시각은 ISO 8601, 한국 표준시(+09:00)로 표시합니다.
  • 호출 한도를 넘으면 429 RATE_LIMITED와 Retry-After 헤더(초)를 반환합니다. 테스트 키 초당 10건, 운영 키 초당 50건.

상담시간

GET/v1/channels/{channelId}/consult-hours
PUT/v1/channels/{channelId}/consult-hours admin

상담시간 외에 들어온 고객 메시지에는 카카오 시스템 메시지(상담 부재)가 자동 발송됩니다. 시스템 메시지는 과금되지 않습니다.

{
  "week": [
    { "day": "mon", "start": "09:00", "end": "18:00" },
    { "day": "tue", "start": "09:00", "end": "18:00" },
    { "day": "wed", "start": "09:00", "end": "18:00" },
    { "day": "thu", "start": "09:00", "end": "18:00" },
    { "day": "fri", "start": "09:00", "end": "18:00" }
  ]

목록에 없는 요일은 상담하지 않는 날입니다. 24시간 상담은 start와 end를 모두 "00:00"으로 지정합니다.

메시지 발송

POST/v1/messages write

상담 세션이 열린 고객에게 메시지를 보냅니다. 세션은 고객이 채널 채팅방에 메시지를 보내거나 상담 연결 버튼을 누르면 생성됩니다. 세션이 없으면 409 NO_SESSION을 반환합니다.

요청 본문

userKeystringO웹훅으로 받은 고객 키

textstring-text일 때 필수. 최대 1,000자
imageUrlstring-image일 때 필수. 이미지 업로드로 받은 URL

richobject-rich일 때 필수. 리치 말풍선 참고
clientMessageIdstring(30)X고객사 메시지 ID. 24시간 안에 같은 값으로 다시 요청하면 처음 결과를 그대로 반환합니다

serial은 발신 취소에 사용합니다. 카카오에 전달하는 serial_number와 같은 값입니다.

리치 말풍선

type: "rich"일 때 rich.bubbleType으로 말풍선 종류를 고릅니다. 리치 말풍선은 기기 글꼴 설정과 관계없이 일정한 크기로 보입니다.

bubbleType구성제약
TEXT메시지 + 버튼 + 쿠폰메시지 최대 1,000자, 줄바꿈 33개
IMAGE이미지 + 메시지 + 버튼 + 쿠폰이미지·메시지 필수
WIDE와이드 이미지 + 메시지 + 버튼 + 쿠폰메시지 최대 76자, 줄바꿈 1개, 버튼 최대 2개
ITEM_LIST이미지 + 헤더 + 하이라이트 + 아이템 + 요약 + 메시지 + 버튼아이템 2~10개, 제목 6자, 설명 23자, 메시지 700자
WIDE_ITEM_LIST헤더 + 아이템 3~4개 + 버튼 + 쿠폰헤더·아이템 필수, 버튼 최대 2개
CAROUSEL_FEED캐러셀 2~6개 + 더보기버튼 최대 2개
PERSONAL개인정보 제공 동의 요청 (고정 문구)세션당 1회, 동의 유효 3일, 결과는 personal_info 웹훅
KAKAO_CERT카카오톡 본인 인증 (고정 문구)별도 계약·화이트리스트 필요, certExpiry 5~20분, 결과는 cert_result 웹훅

리치 본문이 형식에 맞지 않으면 400 INVALID_RICH와 함께 문제가 된 필드 경로를 error.field로 반환합니다. 리치 이미지는 업로드 시 purpose를 말풍선 종류에 맞게 지정해야 합니다.

자동 응답 문구

bubbleType: "TEXT"에 autoAnswer를 지정하면 시스템 자동 응답으로 분류됩니다: S1 상담 불가, S2 상담 부재, S3 무응답 상담 종료, S4 상담 대기, S5 금칙어 상담 불가.

카카오톡 인증

GET/v1/cert/status?channelId={channelId}&userKey={userKey}

KAKAO_CERT 말풍선 발송 후 인증 진행 상태를 조회합니다. 인증 결과는 암호화되어 cert_result 웹훅으로 전달되며, 고객사는 식별 즉시 파기해야 합니다. 카카오톡 인증은 별도 계약과 채널 화이트리스트 등록이 필요하므로 도입 문의로 신청하세요. 인증 완료 건당 별도 과금됩니다.

사용량

GET/v1/usage?from=2026-11-01&to=2026-11-30&channelId={channelId}
{
  "ok": true,
  "data": {
    "plan": { "id": "standard", "quota": 500, "used": 412, "periodEnd": "2026-12-01T04:00:00+09:00" },
    "daily": [ { "date": "2026-11-01", "rooms": 14 }, { "date": "2026-11-02", "rooms": 9 } ]
  }
}

사용량은 카카오 상담톡 세션 통계를 기준으로 매일 04시에 전날 분을 확정합니다. 당일 수치는 잠정치입니다.

웹훅 설정

콘솔 웹훅 메뉴에서 HTTPS 엔드포인트 1개와 받을 이벤트를 고릅니다. 모든 채널의 이벤트가 같은 엔드포인트로 오며 channelId로 구분합니다.

  • 5초 안에 2xx로 응답하세요. 무거운 처리는 큐에 넣고 바로 응답하는 방식을 권장합니다.
  • 카카오 수신 이벤트는 순서를 보장하지 않습니다. 정렬이 필요하면 data.time(카카오 서버 시각)을 기준으로 하세요.
  • 테스트 이벤트는 "test": true가 붙고 userKey가 tc-test-로 시작합니다. 이 고객에게는 답장할 수 없습니다.
  • 상담 메시지는 카카오에 3일만 보관됩니다. 받은 내용과 첨부 파일은 즉시 고객사에 저장하세요. 첨부 URL은 만료 시각이 있습니다.

서명 검증

서명 대상은 {t}.{원본 요청 본문}이며 웹훅 서명 키로 HMAC-SHA256을 계산한 hex 값이 v1입니다. JSON을 다시 직렬화하지 말고 받은 바이트 그대로 검증하세요. t가 현재 시각과 5분 이상 차이 나면 거부해 재전송 공격을 막습니다.

Node.js

import crypto from 'node:crypto';

export function verify(rawBody, header, secret) {
  const parts = Object.fromEntries(header.split(',').map(p => p.split('=')));
  const t = Number(parts.t);
  if (Math.abs(Date.now() / 1000 - t) > 300) return false;
  const expected = crypto.createHmac('sha256', secret).update(`${t}.${rawBody}`).digest('hex');
  const sigs = header.split(',').filter(p => p.startsWith('v1=')).map(p => p.slice(3));
  return sigs.some(s => s.length === expected.length &&
    crypto.timingSafeEqual(Buffer.from(s), Buffer.from(expected)));
}

// Express: 원본 본문 보존
app.post('/webhook', express.raw({ type: 'application/json' }), (req, res) => {
  if (!verify(req.body.toString('utf8'), req.get('X-TC-Signature'), process.env.TC_WEBHOOK_SECRET)) {
    return res.sendStatus(400);
  }
  const event = JSON.parse(req.body);
  queue.push(event);   // 처리는 비동기로
  res.sendStatus(200);
});

Python

import hmac, hashlib, time

def verify(raw_body: bytes, header: str, secret: str) -> bool:
    items = [p.split("=", 1) for p in header.split(",")]
    t = int(dict(items)["t"])
    if abs(time.time() - t) > 300:
        return False
    expected = hmac.new(secret.encode(), f"{t}.".encode() + raw_body, hashlib.sha256).hexdigest()
    return any(k == "v1" and hmac.compare_digest(v, expected) for k, v in items)

Java

public static boolean verify(String rawBody, String header, String secret) throws Exception {
    long t = 0; List<String> sigs = new ArrayList<>();
    for (String p : header.split(",")) {
        String[] kv = p.split("=", 2);
        if (kv[0].equals("t")) t = Long.parseLong(kv[1]);
        if (kv[0].equals("v1")) sigs.add(kv[1]);
    }
    if (Math.abs(Instant.now().getEpochSecond() - t) > 300) return false;
    Mac mac = Mac.getInstance("HmacSHA256");
    mac.init(new SecretKeySpec(secret.getBytes(UTF_8), "HmacSHA256"));
    String expected = HexFormat.of().formatHex(mac.doFinal((t + "." + rawBody).getBytes(UTF_8)));
    for (String s : sigs)
        if (MessageDigest.isEqual(s.getBytes(UTF_8), expected.getBytes(UTF_8))) return true;
    return false;
}

재시도·멱등 처리

  • 5초 안에 2xx 응답이 없으면 1분, 5분, 30분, 2시간, 6시간 간격으로 최대 5회 재시도합니다.
  • 재시도해도 id(X-TC-Delivery)는 같습니다. 처리한 id를 저장해 중복을 거르세요.
  • 모든 재시도가 실패한 이벤트는 콘솔 전송 이력에서 확인하고 수동 재전송할 수 있습니다. 보관 기간 3일.
  • 24시간 동안 연속 실패하면 담당자 이메일로 알리고, 72시간 연속 실패하면 웹훅을 일시 중지합니다.

과금 기준

  • 과금 단위는 상담방 1건이며, 상담원(API)이 메시지를 1회 이상 보낸 상담 세션 1개를 의미합니다. 같은 세션에서 메시지를 여러 번 보내도 1건입니다.
  • 시스템 메시지(상담 부재 등 카카오 자동 발송)는 과금에서 제외됩니다.
  • 카카오 상담톡 세션 통계 기준으로 매일 04시에 집계합니다.
  • 선불 월 요금제 Starter 100건, Basic 300건, Standard 500건, Pro 1,000건. 부가세 별도.
  • 사용량 80%와 소진 시 알림. 소진되면 402 QUOTA_EXCEEDED로 발송이 중단됩니다. Enterprise는 중단 없이 후불 정산.
  • 테스트 채널은 무료 기간(가입일로부터 1개월) 동안 과금되지 않습니다. 무료 이력은 사업자번호 기준 1회.
