톡커넥터 API로
상담톡을 연결합니다

톡커넥터는 카카오 상담톡 API 중계 서버입니다. 고객사가 보낸 요청을 받아 카카오에 그대로 전달하고, 카카오에서 들어온 고객 메시지를 고객사 서버로 전달합니다. 카카오 허브파트너 계약, 발신프로필 등록, 수신 도메인 등록은 톡커넥터가 대신 처리합니다.

고객사 서버상담 시스템
/v3/chat/send/.../message, /reference ...
톡커넥터중계 서버
카카오 상담톡 API수신 콜백
카카오톡고객

처음 연동한다면 이것만 구현하세요

상담 필수

보내기 2개, 받기 3개

메시지 보내기, 상담 종료, 수신 경로 /message /reference /expired_session. 이것만으로 상담이 됩니다.

 부가 기능

필요할 때 추가

읽음 처리, 메시지 삭제, 세션 조회·연장, 고객 차단, 개인정보 동의, 본인 인증.

 채널 설정

코딩 없이 콘솔에서

상담 시작 버튼 링크, 시스템 메시지 문구. 사용량과 요금은 콘솔에서 확인합니다.

연동 준비

콘솔에서 채널을 연결하면 아래 정보가 발급됩니다. 별도 신청 메일이나 서류는 필요하지 않습니다.

항목사용처발급 단위확인 위치
발신프로필 키 sender_keyX-SenderKey 헤더와 요청 본문 sender_key채널마다 1개콘솔 > 채널
API 토큰X-JwtToken 헤더계정당 테스트 1개, 운영 1개콘솔 > API 토큰
Channel Secret수신 요청의 X-Signature 서명 검증계정당 1개콘솔 > 수신 설정

고객사가 콘솔에 등록할 정보는 수신 도메인 하나입니다. 예를 들어 https://cs.your-company.com/kakao를 등록하면 고객 메시지는 https://cs.your-company.com/kakao/message로 들어옵니다.

  • 테스트 채널과 테스트 API 토큰은 가입 후 1개월 동안 무료입니다. 운영 전환 시 발신프로필 키가 새로 발급되고 운영 API 토큰을 써야 합니다.
  • 고객사 방화벽에서 API 도메인으로 나가는 443 포트를 허용하세요. 중계 서버 IP는 바뀔 수 있으므로 IP가 아닌 도메인 기준으로 허용하는 것을 권장합니다.

텍스트, 이미지, 동영상, 오디오, 파일을 보냅니다. 고객이 먼저 메시지를 보내거나 상담 시작 버튼을 눌러 상담 세션이 열린 고객에게만 보낼 수 있습니다.

필드타입필수설명

sender_keytext(40)O발신프로필 키
serial_numbertext(30)O메시지 일련번호. 고객사가 메시지마다 고유하게 생성. 중복이면 -504

메시지 받기

고객사 서버는 콘솔에 등록한 수신 도메인 아래 3개 경로를 구현합니다. 모두 POST, application/json이며 X-Signature 헤더가 붙습니다.

경로호출 시점구분
/message고객이 메시지를 보냄필수
/reference상담 세션 시작. 상담 시작 버튼의 extra 같은 메타 정보 전달필수
/expired_session상담 세션 종료필수
/personal_info /cert_result개인정보 동의, 본인 인증 결과. 부가 기능 참고선택
/seen_info고객이 상담원 메시지를 읽음. 별도 신청 필요선택
  • 바로 200으로 응답하고 처리는 비동기로 하세요. 응답하지 않으면 카카오가 고객에게 "현재 연결이 원활하지 않습니다" 안내를 보내며 해당 메시지는 다시 전달되지 않습니다.
  • 도착 순서는 보장되지 않습니다. 정렬이 필요하면 time을 기준으로 하세요.
  • 상담 메시지는 카카오에 3일만 보관됩니다. 받은 내용과 첨부 파일은 즉시 고객사에 저장하세요. 첨부 URL에는 만료 시각이 있습니다.

서명 검증

수신 요청이 톡커넥터에서 왔는지 X-Signature 헤더로 확인합니다. 값은 HS256 JWT이며, Channel Secret으로 서명되어 있고 클레임 jwtToken에 고객사 API 토큰이 들어 있습니다.

  1. Channel Secret으로 JWT 서명(HS256)을 검증합니다.
  2. 클레임 jwtToken이 고객사 API 토큰과 같은지 확인합니다.
  3. 둘 중 하나라도 실패하면 401로 응답하고 처리하지 않습니다.

Java (jjwt)

Claims claims = Jwts.parser()
    .setSigningKey(CHANNEL_SECRET.getBytes(StandardCharsets.UTF_8))
    .parseClaimsJws(request.getHeader("X-Signature"))   // 서명이 틀리면 예외
    .getBody();
boolean valid = API_TOKEN.equals(claims.get("jwtToken", String.class));

Node.js (jsonwebtoken)

function verify(req) {

}

세션 연장 선택

세션은 고객의 마지막 메시지 후 30일간 유지되고 고객 메시지가 올 때마다 연장됩니다. 고객 응답 없이 세션을 더 유지해야 할 때만 사용합니다. 만료까지 30일 이하로 남았을 때 만료 시각 기준 30일 연장되며, 연장 성공 건별로 과금됩니다.

메서드경로설명
POST/v3/chat/extend메시지 없이 연장. 본문 user_key sender_key
POST/v3/chat/extend/plain안내 메시지와 함께 연장. 본문은 메시지 보내기와 같음
POST/v3/chat/extend/rich리치 메시지와 함께 연장. PERSONAL KAKAO_CERT auto_answer 사용 불가

응답에 연장된 session이 포함됩니다. 응답을 받지 못했으면 다시 요청하기 전에 세션 조회로 연장 여부를 확인하세요. 메시지 발송이 실패하면 세션도 연장되지 않습니다.

개인정보 동의·본인 인증 선택

개인정보 제공 동의

리치 메시지 보내기에서 chat_bubble_type: "PERSONAL"로 보냅니다. 문구는 고정이고 세션당 1회, 동의는 발송 후 3일간 유효합니다. 고객이 동의하면 /personal_info로 닉네임과 전화번호가 전달됩니다.

// /personal_info
{ "user_key": "MZjEVK4x18_V", "sender_key": "{sender_key}", "session_id": 29153, "time": 1793232914261,
  "personal_info": { "phone_number": "821012345678", "nickname": "홍길동" } }

카카오톡 본인 인증

chat_bubble_type: "KAKAO_CERT"와 cert_expiry(분)를 보냅니다. 별도 계약과 채널 등록이 필요하므로 도입 문의로 신청하세요. 과금은 상담방과 별개로 인증 완료 건당입니다. 결과는 /cert_result로 암호화되어 전달되며, 복호화 키는 계약 시 안내합니다.

GET/v3/chat/cert/status?cert_tx_id={cert_tx_id}

인증 진행 상태 sign_status를 조회합니다: NOT_COMPLETED 진행 중, COMPLETED 완료, EXPIRED 만료.

개인정보와 인증 정보는 톡커넥터에 저장되지 않습니다. 고객사도 상담 종료 후 지체 없이 파기하고, 인증 정보는 고객 식별 즉시 파기해야 합니다.

상담 시작 버튼

홈페이지나 앱에서 고객이 상담을 시작하게 하는 링크입니다. API 호출 없이 카카오 주소로 바로 연결하며, 콘솔 채널 화면에서 복사할 수 있습니다.

https://bizmessage.kakao.com/chat/open/@채널검색용아이디?extra=order_1234
파라미터설명
extra/reference로 전달할 메타 정보. 영문, 숫자, 밑줄 50자 이내. 개인정보 금지
bottrue면 봇으로 시작, auto면 봇으로 시작하되 진행 중인 상담이 있으면 상담 유지
event봇으로 시작할 때 실행할 블록 이벤트명
app_open_type모바일에서 카카오톡 실행 방식. modal(기본) 확인 팝업 후 실행, direct 즉시 실행

extra를 1,000자까지 보내야 하면 같은 주소에 POST 폼으로 uuid(채널 아이디)와 extra를 전송합니다. 새 창이나 팝업(권장 1024x800)으로 열어야 합니다.

시스템 메시지

상담 시작, 상담 종료 등 정해진 시점에 카카오가 자동으로 보내는 안내입니다. 콘솔 채널 화면에서 문구를 바꾸고 검수를 요청하면 카카오 검수(보통 3영업일) 후 적용됩니다. 시스템 메시지는 과금되지 않습니다.

코드구분발송 시점
ST상담 시작세션 시작 시. #{위탁사명}, 저장 안내, "!종료" 안내 필수
S1~S4상담 불가, 부재, 무응답 종료, 대기고객사가 auto_answer로 요청할 때
ED상담 종료고객 요청으로 종료될 때
-응답 실패고객사 수신 서버가 응답하지 않을 때

문구는 각 200자 이내, 광고 불가, URL은 고객센터 주소만 가능합니다.
